# Этапы улучшения Quanta

Выполняй строго по порядку, по одному этапу за сессию. Общие правила — в AGENTS.md.
Статус каждого этапа веди в docs/PROGRESS.md.

## Известные факты из аудита
Проверь каждый на реальном коде. Если пункт не подтвердился, запиши в отчёт и ничего не чини.
- fetch_url (assistant/tools.py) имеет риск read, то есть без подтверждения. Нет фильтра внутренних адресов (SSRF), редиректы следуются без проверки. _curl_get без --max-filesize, --max-redirs, --proto.
- read_file имеет риск read. Проверь, ограничивает ли _resolve доступ рабочей папкой и защищены ли чувствительные пути (.env, .ssh, профили браузеров, data/settings.json с api_key).
- memory_save имеет риск low, возможна запись из недоверенного контекста (отравление памяти).
- Нет Content-Security-Policy. Токен сессии вшивается в index.html. В ui/app.js 47 использований innerHTML.
- api_key и fallback_api_key лежат в settings.json открытым текстом.
- Монолиты: tools.py (~2140 строк, метод _register ~330 строк), app.js (~3600), server.py (~1360, ручной роутинг), agent.py (Agent.run ~500 строк), storage.py (~1080).
- Данные: ~10 JSON-файлов и по файлу на чат, без SQLite, без версий схемы и миграций.
- Окончания строк смешаны (CRLF и LF). 5 тестов падают вне Windows из-за жёстко заданного пути /Desktop. CI только Windows, сборку и smoke_packaged_app.ps1 не запускает.
- Нет eval-набора и трассировки ходов агента. Версия 0.1.0, механизма обновлений нет.

## Этап 1. Срочная безопасность
1.1 SSRF в fetch_url и всех исходящих запросах, инициируемых моделью: только http/https; резолв хоста и запрет private, loopback, link-local, reserved, multicast, unspecified (включая IPv6 и v4-mapped, десятичные/восьмеричные/hex-формы IP, localhost-алиасы); редиректы обрабатывать вручную (максимум 5, проверка каждого перехода); защита от DNS rebinding (подключение к проверенному IP либо повторная проверка). Для curl-фолбэка: --proto =http,https, --proto-redir =http,https, --max-redirs 5, --max-filesize 2000000, та же проверка адреса. Обращения к адресу Ollama из настроек не затрагивай.
1.2 Цепочка «чтение → наружу»: если в текущем ходе агент прочитал файл, буфер обмена, экран или UIA-дерево, любой сетевой инструмент в этом же ходе требует подтверждения с показом полного URL и предупреждением об утечке. Режим auto это не отключает.
1.3 read_file: проверить _resolve. Чувствительные пути (.env, .ssh, профили браузеров, хранилища паролей, data/settings.json и другие данные самой Quanta) либо запрет, либо подтверждение с предупреждением.
1.4 memory_save: подтверждение, если в ходе были недоверенные данные (веб, файл, экран, MCP). Записи памяти в системном промте помечай как данные пользователя, а не как инструкции.
1.5 Content-Security-Policy для UI (default-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; img-src 'self' data: blob: по необходимости). Проверь, что UI работает; если есть inline-скрипты или стили, вынеси их в файлы, а не ослабляй политику.
1.6 Ключи API: защищённое хранение (DPAPI через ctypes без новых зависимостей, либо keyring с обоснованием), миграция существующих ключей из settings.json, в ответах API и логах только маска, в UI ключ не возвращается.
1.7 SECURITY.md: модель угроз, что считается недоверенным, что и когда подтверждается, как сообщать об уязвимостях.
1.8 Тесты: SSRF (127.0.0.1, 10.x, 192.168.x, 169.254.169.254, ::1, localhost, редирект на внутренний адрес, нестандартные формы IP), цепочка чтение→сеть, чувствительные пути, заголовок CSP, маскирование ключа.
Готово, когда: все пункты реализованы, новые тесты проходят, старые не сломаны.

## Этап 3. Рефакторинг без изменения поведения
- Сначала характеризационные тесты на то, что ещё не покрыто (Toolbox, события Agent.run, маршруты сервера).
- tools.py → пакет assistant/tools/ по областям (файлы, ПК, веб, память и заметки, музыка, Minecraft, 3D и т.д.). Регистрация через декоратор `@tool(name, label, risk, confirm, capabilities=[...], network=True)` вместо метода `_register`; публичный API Toolbox не меняется. `capabilities` — обязательный непустой аргумент без значения по умолчанию. `network=True` включён по умолчанию; инструмент без сети обязан явно объявить `network=False`. Добавь тесты на обязательность `capabilities`, сетевой default-on и явный opt-out.
- Agent.run → набор небольших методов (подготовка контекста, цикл шагов, обработка вызова, подтверждение, финализация) с типизированными событиями. Внешний поток событий для UI не меняется.
- server.py → модули маршрутов с таблицей маршрутов и валидацией входных данных. Проверки Host, Origin, токена остаются без изменений.
Готово, когда: все прежние тесты проходят без изменения ожиданий, нет файла длиннее ~600 строк в новых модулях, нет циклических импортов, поведение сверено характеризационными тестами.

## Этап 4. Трассировка и eval-набор
- **Сессия 4a — трассировка и UI:** трасса хода (модель, шаги, вызовы инструментов с редактированием секретов и паролей, задержки, ошибки, решения о подтверждении), JSONL с ротацией в `data/traces/` и просмотр в отдельной вкладке UI. По завершении зафиксировать проверенный результат и остановиться.
- **Сессия 4b — eval-набор:** только после завершения 4a, в отдельном рабочем сеансе. Eval-раннер (`python -m tools.evals`), сценарии в JSON/YAML (запрос → ожидаемые вызовы и итоговое состояние), изолированная временная папка и mock-инструменты без реальных действий над ПК. Два режима: replay с записанными ответами модели (детерминированный, идёт в CI) и live с Ollama (запуск вручную). Отчёт с долей успеха по моделям в `evals/results/`.
- Минимум 25 сценариев: файлы, поиск, заметки, напоминания, память, отказ от опасных действий, устойчивость к prompt injection (инструкции внутри веб-страницы, файла или экрана не исполняются и не вызывают сеть). Не начинать 4b в том же рабочем сеансе, что 4a.
Готово, когда: replay-режим работает в CI, есть отчёт, трассы видны в UI.

## Этап 5. SQLite вместо JSON
- stdlib sqlite3, режим WAL, таблица версии схемы и миграции вверх. Потокобезопасность (соединение на поток или очередь записи).
- Автоматический импорт существующих JSON при первом запуске с предварительной резервной копией; оригиналы не удалять.
- FTS5 для чатов и памяти (с запасным путём, если FTS5 недоступен).
- Экспорт всех данных в zip, резервная копия и восстановление, «Забыть всё» с подтверждением.
- Тесты миграции на образцах старого формата, включая повреждённые файлы.
Готово, когда: приложение работает на SQLite, старые данные переносятся без потерь, тесты миграции проходят.

## Этап 7. Движок политик и изоляция
- assistant/policy.py: каждый инструмент объявляет capabilities (читает_личное, сеть_наружу, пишет_файлы, исполняет, ввод_в_ПК, пишет_память). Отслеживай taint сессии: источники недоверенных данных (веб, файл, экран, UIA, MCP, буфер). Правило: taint + (сеть_наружу | запись | исполнение | ввод | запись памяти) = подтверждение с объяснением причины. Режимы safe/smart/auto сохраняются, но auto не отключает правила taint для сети и исполнения. Решения пишутся в трассу, таблица правил покрыта тестами.
- Опасные инструменты (исполнение, запись файлов, ввод в ПК) выполняются в отдельном дочернем процессе-исполнителе с узким IPC; ядро напрямую их не вызывает.
- Для command_sandbox добавь запасной вариант изоляции, когда Windows Sandbox недоступна (Job Object и ограниченный токен либо иное обоснованное решение). Сохрани fail-closed и честно показывай пользователю фактический уровень изоляции.
Готово, когда: правила политики работают и тестируются, исполнитель вынесен, Windows-части помечены как не проверенные на Windows с шагами ручной проверки.

## Этап 10. Релиз
- Workflow по тегу: build_windows.ps1 → smoke_packaged_app.ps1 → артефакты, SHA256, SBOM (CycloneDX).
- Подпись кода: шаг с секретом из GitHub secrets; если секрета нет, пропуск с явным предупреждением, без имитации.
- Semver, версия из одного источника.
- Проверка обновлений только по явному включению пользователем, проверка SHA256 и подписи до установки, без тихой установки.
- Локальный отчёт об ошибке (zip с логами и редактированием секретов) по кнопке, без автоотправки.
Готово, когда: workflow описан и логически проверен; всё, что нельзя запустить вне Windows и без секретов, помечено как не проверенное.
