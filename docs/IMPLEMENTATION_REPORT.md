## Принятые решения и допущения

- Имеющиеся изменения рабочего дерева присутствовали до первой правки; их сохраняем и не откатываем.
- Для HTTP-инструментов принята fail-closed стратегия: если у DNS-имени есть хотя бы один непубличный ответ или имя нельзя безопасно разрешить, запрос отклоняется. TLS проверяется по исходному имени, TCP подключается к закреплённому IP.
- Сервер создаёт неизменяемый dataclass `RouteContext` из текущих зависимостей модуля и передаёт его в обработчики маршрутов. Это сохраняет актуальные подмены тестов и работу при импорте `server` или запуске файла как `__main__`. Host/Origin/session-проверки выполняются до передачи запроса в таблицу.
- Чувствительные пути не запрещены полностью: для сохранения возможности диагностики они доступны только после явного подтверждения с предупреждением.
- Память сериализуется JSON-массивом, чтобы содержимое пользовательских записей не могло выглядеть как отдельные строки системных правил.
- MCP здесь запускает только stdio-процессы и всегда требует подтверждения; локальные CDP/Ollama-запросы оставлены без изменений. Открытие URL в браузере остаётся отдельным подтверждаемым действием.
- CSP разрешает ресурсы только с текущего origin, `data:`/`blob:` для изображений и `blob:` для медиа; `unsafe-inline` не добавлялся.
- Ключи хранятся в `data/api_secrets.json` как DPAPI-защищённый payload пользовательского контекста; `settings.json` хранит только обычные настройки. При отсутствии Windows DPAPI миграция или запись ключа завершается ошибкой, открытый fallback не используется.
- Кеш и загрузка модели Silero `v4_ru.pt` сверяются с закреплённым SHA-256; voice playback и фактическая загрузка модели через torch.package не проверялись. Ручная проверка на Windows: выбрать Silero, запустить пробное воспроизведение, затем сверить SHA файла в `%PUBLIC%\\Quanta\\models\\silero\\v4_ru.pt` с `SILERO_MODEL_SHA256`.
- Проверка фактов аудита безопасности подтвердила `risk="read"` у `fetch_url` и `read_file`, `risk="low"` у `memory_save`; специальные подтверждения покрывают чувствительные пути и доверительные цепочки. Токен сессии генерируется для процесса и добавляется в HTML при выдаче, в статическом файле хранится placeholder. Остались 47 присваиваний `innerHTML`; CSP не заменяет контекстное экранирование.
- `.gitattributes` задаёт LF для текста и CRLF для `.bat`, `.cmd`, `.ps1`; 14 файлов нормализованы отдельной операцией без логических правок. Три локальных диагностических файла не тронуты; их адресные ignore-строки удалены из `.gitignore`.
- Аудит не нашёл тестов с реальными `/Desktop` путями; тестовые файлы используют временные каталоги, DPAPI-тест помечен явным платформенным пропуском.
- Ruff и `pip-audit` закреплены в `requirements-dev.txt`; использованы правила Ruff `E4`, `E7`, `E9`, `F`. Полные SHA GitHub Actions сверены по тегам релизов официальных репозиториев.
- Исходный подробный README сохранён в `docs/USER_GUIDE.md`; краткий README содержит запуск и ссылки. MCP-пример выключен по умолчанию, а его локальный echo-сервер прошёл stdio list/call без сетевых обращений.

## Не проверено на Windows

- Windows Sandbox, UI Automation, упаковка, установщик и упакованное приложение пока не проверялись. Ручные шаги будут добавлены при соответствующих пунктах.
- На этапе 3 реальные действия Windows UI Automation/ПК/музыки не запускались. Ручная проверка: запустить `python server.py`, открыть локальный интерфейс, проверить список приложений, отклонить подтверждение действия в smart и убедиться, что действие не выполнено, затем проверить предупреждение при чтении чувствительного пути.
